## 2. 迭代计划（解决 V2.0 里程碑 P2/P3 重叠问题）

> 文档原里程碑以"系统"为阶段，易在第 7 月冲突。改为**先纵向打通、再横向铺满**。

### Iteration 0（本次交付，端到端地基 + 核心闭环）
- 范围：WP0–WP12 的核心部分，打通 §6 全链路 + RAG/根因。
- 出口标准：`docker compose up -d` 后，能用演示账号完成一遍"收货→IQC→上架→领料→报工→完工→OQC→出库"，并能跑通一次 NCR→CAPA，RAG 可问答。

### Iteration 1（横向补 WMS/QMS 广度）
- WMS：盘点（循环/动盘/差异审批）、波次策略完善（摘果/播种/边拣边分）、路径优化、复核打包称重、计费、多货主深化。
- QMS：SPC 八大判异、控制图全类型、供应商绩效自动评分/分级、8D 全流程、质量成本 PAF 报表。
- AI：OCR 仪表读数、需求/库存预测。

### Iteration 2（MES 深化 + IoT + 视觉）
- MES：可视化工厂建模、Andon 全流程、电子看板/SOP 推送防错、OEE 全量、JIT 物料拉动、APS 齐套检查与插单模拟。
- IoT：EMQX + OPC UA + TimescaleDB，边缘网关断网续传。
- AI 视觉：标注体系 + YOLOv8/ONNX + 人工复核回流（先试点线）。

### Iteration 3（智能化 + 生产化）
- 预测性维护（LSTM/Isolation Forest）、智能排产（GA/RL）、RAG 升级向量库 Milvus。
- 治理与上生产：Nacos/Sentinel/Seata、RocketMQ、ClickHouse、K8s/Helm/ArgoCD、可观测三件套、备份灾备演练。

### 与原文档里程碑映射
| 原阶段 | 重新落位 |
|---|---|
| P1 基础平台+MES 核心 | Iteration 0（system + mes 核心） |
| P2 WMS 全模块 | Iteration 0（核心）+ Iteration 1（全量） |
| P3 QMS 全模块 | Iteration 0（核心）+ Iteration 1（全量），与 WMS 错峰 |
| P4 AI 赋能 | Iteration 0（RAG/根因）+ Iteration 1/2/3（其余） |
| P5 推广优化 | Iteration 3 起 |

## 4. 完成定义（DoD）

**通用 DoD（每个任务都必须满足）**
1. 代码可编译/构建，无阻断性告警；遵循统一响应与错误码。
2. 关键路径有自测（接口可在 Swagger/脚本中跑通）；异常分支有处理与提示。
3. 涉及状态变更：有前置状态校验，非法跳变返回 1009/4011 等。
4. 涉及库存：条件更新防超扣；写操作幂等。
5. 提交信息清晰；无密钥/口令硬编码；公共逻辑沉淀到 common。
6. 对应前端（若需要）可完成操作闭环；Docker 下服务健康检查通过。

**服务级 DoD**
- system：能登录、能维护闭环所需全部主数据。
- wms：账实一致（每次变动可追溯单据）、FIFO 正确、超扣被拦截。
- qms：判定结果与上下限/AQL 一致；不合格必产生 NCR 且能闭环。
- mes：工单状态不可非法跳变；报工数量累计正确；谱系可正反向查询。
- ai：回答带引用；无据明确转人工；无 key 可离线演示。

## 5. 验收标准（映射业务 KPI）

| 业务目标 | 验收用例 |
|---|---|
| 业务线上化 | 核心闭环全程无纸质单据，系统内完成全部操作 |
| 全链路追溯 | 给定成品批次，秒级反查物料批次/设备/人员/工单；给定物料批次正查受影响成品 |
| 质量闭环 | 制造一个不合格项，验证：自动冻结 → NCR → MRB → CAPA → 验证关闭，全程留痕 |
| 库存精准 | 收/发后库存与单据一致；FIFO 推荐按效期；模拟超扣被拦截；冻结批次不可出库 |
| AI 赋能 | RAG 对知识内问题给出带引用答案；对知识外问题明确转人工；根因输出 5M1E 排序 |
| 可部署 | 全新环境 `docker compose up -d` 后健康检查全绿，按 README 可完成演示 |

## 6. 风险登记册

| 风险 | 等级 | 应对 |
|---|---|---|
| 视觉/预测性维护缺标注与历史数据 | 高 | 后移至 Iter2/3，先建数据采集与标注体系 |
| 跨服务 Feign 编排失败导致半成品状态 | 中 | 状态前置校验 + 幂等 + 可读错误 + 补偿；二期 MQ/Saga |
| 试点环境资源不足（多容器） | 中 | 裁剪中间件、合理 JVM 堆、服务可选启停 |
| 主数据冗余快照不一致 | 低 | 冗余 `_name` + 二期事件刷新/对账 |
| 云端 LLM 泄密/合规 | 中 | 仅传必要片段；敏感场景走本地模型/合规网关；key 走环境变量 |
| 范围蔓延（一次想做全） | 高 | 严守垂直切片边界，新增需求进迭代 Backlog |
