## 4. 各阶段测试详情

### 4.1 鉴权与安全（13/13）
- 无 Token 访问物料、WMS 库存接口 → `code=1003 / HTTP 401`。
- 伪造 Token、非法格式 Token → 均被拒绝（1003 / 401）。
- 白名单 `/api/ai/health` 可匿名访问，返回 `status=UP`。
- 错误密码、不存在用户登录 → `code=1001`。
- admin 正确登录签发 JWT（长度 291），`/me` 正确解析当前用户。
- planner / warehouse / inspector / operator 四个角色账号均能正常登录。

### 4.2 system 主数据（13/13）
种子数据完整：组织 8、角色 5、用户 5、物料 6、供应商 2、工作中心 4、BOM 1、工艺路线 1。
- BOM `5001` 详情含 **5 个明细**（PCB×1、外壳×1、芯片×1、螺丝×4、包装盒×1）。
- 工艺路线 `6001` 详情含 **4 道工序**（SMT 贴片→整机组装→功能测试→包装入库）。
- 物料 `1001` 详情为 `FG-100`；关键字 `RM` 命中 4 条原材料、`SUP` 命中 2 条供应商。

### 4.3 链路 A：收货→IQC→上架（10/10）
- 收货单 `RC20261010172757141`：PCB 主板 100 件，自动在待检库位 `RECV-01` 建立 PENDING 库存 100。
- 自动建立 IQC 任务并命中标准 `STD-PCB-IQC`；录入长度 100.0（规格 99.8–100.2）、厚度 1.6（1.5–1.7）、外观 OK → 判定 QUALIFIED。
- 合格自动生成上架任务，推荐库位 `A-01-01`，执行上架：待检库存清零、目标库位 QUALIFIED 库存 100。

### 4.4 链路 B：工单→生产→出库（19/19）
- 按 BOM 自动备齐 5 种原材料合格库存（PCB 150、外壳 50、芯片 50、螺丝 200、包装盒 50）。
- 工单 `WO20261010173058290`（计划 10 台）→ 下达生成领料波次 `WV20261010173059562`，按 BOM 展开并 FIFO 分配批次。
- 执行整波拣货，条件扣减合格库存，波次 PICKED；线边交接回写投料记录与谱系，工单 PICKED。
- 开工 STARTED → 报工合格 10 件（qtyCompleted=10）→ 完工生成成品批次 `FG20261010173103670`，成品入成品仓并自动建立 OQC。
- OQC（功能/外观/包装）判定合格放行，成品仓 QUALIFIED 库存 10。
- 出库单 `OB20261010173107351` → 确认发运 SHIPPED，成品库存清零。
- 反向追溯（成品批次→原料批次）返回 5 条子件记录，正向追溯接口可用。

### 4.5 链路 C：NCR→MRB→CAPA + SPC（13/13）
- IQC 提交长度超差（实测超上限）→ 任务 UNQUALIFIED，批次自动冻结（FROZEN 50）。
- 自动生成 NCR `NCR20261010173323327`（OPEN）。
- MRB 评审处置 SCRAP → NCR REVIEWED，WMS 联动将库存置为 SCRAPPED（50），并自动生成 CAPA `CAPA20261010173325014`（OPEN）。
- 录入根本原因/纠正措施/预防措施并执行 → CAPA IN_PROGRESS；质量部验证通过 → CAPA CLOSED，关联 NCR 联动 CLOSED。
- SPC：录入 20 个受控数据点，控制图返回均值/UCL/LCL（mean=100.004）；过程能力 **Cp=2.587、Cpk=2.564（>1.33，过程能力充分）**。

### 4.6 AI 服务（9/9）
- 健康检查 UP，知识库加载 **23 个文档块**。
- 未授权访问 `/ai/chat` 被拦截（1003/401）。
- RAG 问答返回答案（长度 545）并附带 4 条检索来源。
- 纯乱码问题（词项在知识库不存在）检索为空，返回"未检索到、建议转人工"兜底，不臆造。
- 根因分析返回分析文本与 3 条"人/机/料/法/环"可能原因。
- 当前未配置 API Key，`llm_enabled=false`，自动走内置 Mock，流程完整。

### 4.7 异常与边界（12/12）
- 登录缺密码 → 1004；非法 JSON 报文 → 1004（详见第 5 节修复）。
- 查询不存在 ID 返回空数据；出库超扣库存 → 3011。
- 未下达即开工、未拣货即线边交接、无合格报工即完工 → 均 1009。
- 检验任务重复提交、NCR 重复 MRB、CAPA 未执行即验证、上架任务重复执行、出库单重复发运 → 均 1009，状态机保护有效。

## 5. 测试中发现并修复的问题

### 5.1 应用代码缺陷（已修复并回归验证）
| 编号 | 问题 | 修复 | 状态 |
|---|---|---|---|
| D-01 | 非法/不可读请求报文（`HttpMessageNotReadableException`）原本落入兜底，返回 `1500 系统异常`，会把**客户端坏请求误报为系统故障**，干扰监控与告警判断 | 在 `smart-common` 的 `GlobalExceptionHandler` 中新增 `HttpMessageNotReadableException → 1004 参数错误` 映射，并顺带补充 `MethodArgumentTypeMismatchException → 1004` | 已重建 `system-service` 并回归，返回 1004，**通过** |

### 5.2 测试框架 / 环境问题（非应用缺陷，已根治）
| 编号 | 现象 | 处理 |
|---|---|---|
| T-01 | 无 BOM 的 UTF-8 `.ps1` 被 Windows PowerShell 以 ANSI 读取，中文乱码破坏字符串解析 | 所有测试脚本统一保存为 UTF-8 BOM |
| T-02 | curl 默认走系统代理 `127.0.0.1:7897`（代理未运行）导致请求失败 | 测试框架固定 `--noproxy "*"` |
| T-03 | PowerShell 向 curl 传 JSON 时双引号被剥离，后端报 JsonParseException | 请求体统一写临时文件并 `--data-binary @file` |
| T-04 | 结果数组被 ConvertTo-Json 序列化为单对象 | 改用强类型 `List[object]` 并强制平铺数组 |
| T-05 | SPC 初版测试数据波动过大导致 Cpk=1.11 不达阈值 | 收窄数据波动（测试数据设计问题），回归 Cpk=2.56 |
| T-06 | AI"未命中"用例含中文单字被模糊检索命中 | 改用纯乱码输入，检索为空，正确触发兜底 |

## 6. 已知限制与改进建议

1. **通用详情接口 404 规范化**：`BaseCrudController` 的 `GET /{id}` 对不存在 ID 当前返回 `code=0, data=null`，建议改为 `code=1005 / HTTP 404`，语义更清晰（本次测试按现状断言）。
2. **对象存储**：MinIO 因公共镜像源拉取受限，默认置于 `storage` profile（不启动），附件/文件能力暂未启用；网络可达后 `--profile storage` 一键启用。
3. **大模型接入**：AI 服务未配置 `LLM_API_KEY` 时走内置 Mock。在 `.env` 填入 OpenAI 兼容接口的 `base_url / api_key / model` 后即获得完整智能问答与根因分析（`llm_enabled=true`）。
4. **跨服务一致性**：服务间 Feign 调用失败目前采用 warn 降级、不回滚（如 IQC 推送、成品入库）。建议二期引入消息队列或本地消息表 + 对账补偿，保证最终一致性。
5. **测试深化**：建议补充并发/压力测试（JMeter/wrk）、前端组件 E2E 自动化（Playwright）、以及 CI 流水线中自动执行本测试套件。
