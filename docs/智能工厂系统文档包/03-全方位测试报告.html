5. 测试中发现并修复的问题

5.1 应用代码缺陷（已修复并回归验证）

编号问题修复状态
D-01非法/不可读请求报文（HttpMessageNotReadableException）原本落入兜底，返回 1500 系统异常，会把客户端坏请求误报为系统故障，干扰监控与告警判断在 smart-common 的 GlobalExceptionHandler 中新增 HttpMessageNotReadableException → 1004 参数错误 映射，并顺带补充 MethodArgumentTypeMismatchException → 1004已重建 system-service 并回归，返回 1004，通过

5.2 测试框架 / 环境问题（非应用缺陷，已根治）

编号现象处理
T-01无 BOM 的 UTF-8 .ps1 被 Windows PowerShell 以 ANSI 读取，中文乱码破坏字符串解析所有测试脚本统一保存为 UTF-8 BOM
T-02curl 默认走系统代理 127.0.0.1:7897（代理未运行）导致请求失败测试框架固定 --noproxy "*"
T-03PowerShell 向 curl 传 JSON 时双引号被剥离，后端报 JsonParseException请求体统一写临时文件并 --data-binary @file
T-04结果数组被 ConvertTo-Json 序列化为单对象改用强类型 List[object] 并强制平铺数组
T-05SPC 初版测试数据波动过大导致 Cpk=1.11 不达阈值收窄数据波动（测试数据设计问题），回归 Cpk=2.56
T-06AI"未命中"用例含中文单字被模糊检索命中改用纯乱码输入，检索为空，正确触发兜底

6. 已知限制与改进建议

  1. 通用详情接口 404 规范化：BaseCrudController 的 GET /{id} 对不存在 ID 当前返回 code=0, data=null，建议改为 code=1005 / HTTP 404，语义更清晰（本次测试按现状断言）。
  2. 对象存储：MinIO 因公共镜像源拉取受限，默认置于 storage profile（不启动），附件/文件能力暂未启用；网络可达后 --profile storage 一键启用。
  3. 大模型接入：AI 服务未配置 LLM_API_KEY 时走内置 Mock。在 .env 填入 OpenAI 兼容接口的 base_url / api_key / model 后即获得完整智能问答与根因分析（llm_enabled=true）。
  4. 跨服务一致性：服务间 Feign 调用失败目前采用 warn 降级、不回滚（如 IQC 推送、成品入库）。建议二期引入消息队列或本地消息表 + 对账补偿，保证最终一致性。
  5. 测试深化：建议补充并发/压力测试（JMeter/wrk）、前端组件 E2E 自动化（Playwright）、以及 CI 流水线中自动执行本测试套件。
